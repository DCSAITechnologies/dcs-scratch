## 3. Console data modes

| Mode | When | Behaviour |
|---|---|---|
| **demo** | `VITE_COS_API_URL` unset (the public build) | Fixtures under a **DEMO / NON-PRODUCTION** banner. No requests are made. Actions carry truthful maturity labels. |
| **api** | `VITE_COS_API_URL` set | Every page reads and writes `/v1` (`src/pages/dash/api/*`). Errors render as states. Fixtures are never imported here (gate C8). An identity is required. |

Environment variables are public and compiled into the bundle, so never put a secret in one:
- `VITE_COS_API_URL`
- `VITE_OIDC_ISSUER`, `VITE_OIDC_CLIENT_ID`, `VITE_OIDC_SCOPE`, `VITE_OIDC_AUDIENCE`
- `VITE_CONTACT_ENDPOINT`, `VITE_TURNSTILE_SITE_KEY`
- `VITE_COS_DEV_TOKENS`: honoured only in development, mock and core builds. Gate C9 fails if a hermetic token reaches `dist/`.

Templates: `.env.example`, `.env.mock` and `.env.core`.

## 5. Findings from running against core

1. **Restore.** Contract 1.0.0 and core's reference server do **not** enforce a second identity on kill-order restore; they record the reviewer. The mock used to refuse it, which was invented. The mock and the console copy now match core. Marketing copy still describes dual-control restore: confirm cos-runtime's semantics (`STAGING_READINESS.md` #12).
2. **CORS.** Core sends no CORS headers. The console must be served same-origin with `/v1` proxied, or staging must allow the console origin.
3. **Staging server ≠ contract 1.0.0.** `apps/staging-server` serves a tenant-path surface (`/v1/tenants/<t>/…`) with per-action attestations and no list endpoints. Contract 1.0.0's production adapters are `BLOCKED_BY_LANE3`. **This is the main blocker to a real staging console** (`STAGING_READINESS.md`).

## 7. Guard rails

- Counts are always derived; the stale-count gate scans 83 files. Featured ids live in `src/lib/featured.json`, and the build fails on a held id.
- Never hand-edit `connectors*.json`, the inventory or `core-snapshot/`: regenerate them. Never append a provider that core does not list.
- A new console page needs a demo version and an API version (`pick`). Mutations go through `MutationButton`.
- Labels: WIRED, HERMETIC ONLY, PLANNED, EXTERNAL DEPENDENCY, STAGING ONLY, SNAPSHOT.
- No production deploys, secret changes or data changes were made. Core was not modified.
